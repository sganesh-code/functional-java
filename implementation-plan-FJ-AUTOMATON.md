# Implementation Plan: Generalized Effectful State Automaton (FJ-Automaton)
**Target Repository:** functional-java
**Reference Design:** @PROPOSAL-FJ-AUTOMATON.md

The following tickets break down the implementation of the Generalized Effectful State Automaton (FJ-Automaton) epic. All tasks are completed.

---

- [x] **🎟️ [TICKET-001]: Define Core Automaton Interfaces**
  - **Description:** Define the foundational functional interfaces and data models for the automaton logic, side-effects, and persistence.
  - **Scope:**
    - **In scope:** `Machine`, `Interpreter`, `Repository` interfaces and the `Machine.Result` model.
    - **Out of scope:** The orchestrator engine (Automaton).
  - **Implementation Tasks:**
    - [x] Create package `io.github.senthilganeshs.fj.automaton`.
    - [x] Define `@FunctionalInterface Machine<S, I, O>` with a `transition` method.
    - [x] Implement `record Result<S, O>(S state, List<O> commands)` inside `Machine`.
    - [x] Define `@FunctionalInterface Interpreter<F, O, I>` with `Higher<F, List<I>> execute(O command)`.
    - [x] Define `Repository<F, K, S>` with `load(K key)` and `save(K key, S state)` returning `Higher<F, ...>`.
    - [x] Add basic Javadoc to all interfaces based on `@PROPOSAL-FJ-AUTOMATON.md`.

- [x] **🎟️ [TICKET-002]: Implement Generalized Automaton Engine**
  - **Description:** Build the `Automaton` orchestrator that drives the state transitions, persists state changes, and executes side-effects in a recursive loop.
  - **Scope:**
    - **In scope:** `Automaton<F, K, S, I, O>` implementation using `Monad<F>` for orchestration.
    - **Out of scope:** Specialized support for `Task` (handled in TICKET-003).
  - **Implementation Tasks:**
    - [x] Implement `Automaton<F, K, S, I, O>` in `io.github.senthilganeshs.fj.automaton`.
    - [x] Ensure the constructor accepts `Machine`, `Interpreter`, `Repository`, and `Monad<F>`.
    - [x] Implement the `run(K key, I input)` method to perform checkpointing (save before effects).
    - [x] Implement the feedback loop logic to handle recursive inputs generated by the interpreter.
    - [x] Use `Traversable` or similar logic to aggregate command results if necessary.

- [x] **🎟️ [TICKET-003]: Task-Specific Automaton Support**
  - **Description:** Provide ergonomic support for using `Automaton` with the library's `Task` type, which is the primary effect type in FJ.
  - **Scope:**
    - **In scope:** Factory methods or specialized constructor for `Task`.
  - **Implementation Tasks:**
    - [x] Add a static factory method `ofTask` to `Automaton` that automatically uses `Task.monad`.
    - [x] Ensure `Interpreter` and `Repository` can be easily implemented using `Task` without explicit HKT wrapping where possible (using `narrowK` if needed).

- [x] **🎟️ [TICKET-004]: Unit Testing for Automaton**
  - **Description:** Develop a suite of unit tests to verify the correctness of the Automaton engine across various scenarios.
  - **Scope:**
    - **In scope:** Unit tests for transitions, side-effect feedback, and persistence.
  - **Implementation Tasks:**
    - [x] Create `src/test/java/io/github/senthilganeshs/fj/automaton/AutomatonTest.java`.
    - [x] Test a simple "Counter" or "Toggle" automaton with no side effects.
    - [x] Test an automaton where commands generate further inputs (recursion).
    - [x] Verify that `save` is called before `execute`.
    - [x] Test error scenarios (e.g., persistence failure).
